# 本机桌面安装与后续更新

用户于 2026-10-27 明确要求：将新版安装到桌面；以后每次完成新版，直接覆盖同一桌面位置。

用户于 2026-10-28 补充要求：以后交付完整的 Windows 安装包，方便直接发给同学。从 1.0.0 开始，交付标准为可双击安装的单文件 EXE：包含 Electron 与所有计算依赖，创建桌面快捷方式，支持覆盖升级和卸载，保留实验数据。不要求接收者安装 Node.js、下载运行库或手动解压。历史便携 ZIP 继续作为回退材料保留。

- 固定程序目录：`<USER_HOME>\Desktop\控小助程序`
- 固定快捷方式：`<USER_HOME>\Desktop\控小助.lnk`
- 实验与设置目录：`%APPDATA%\控小助`，安装更新不删除、不替换此目录。
- 项目源码与历史发行包继续保留在本项目内。

完成新版发行包及打包程序验证后，在 PowerShell 中运行：

```powershell
& .\scripts\install-desktop.ps1
```

脚本读取项目当前版本，从对应的 `release\控小助-版本-win32-x64` 目录按发布清单复制并校验全部文件，正常关闭运行中的软件后替换桌面程序，更新同一个快捷方式并启动。桌面位置在项目写入范围外时，需通过工具的权限审查；用户已授权这一安装行为。

旧程序目录保留在 `release\desktop-backups` 中，方便回退。关闭时若保存失败或用户取消退出，安装会停止，不强制结束进程。不要只复制 EXE，程序需要同目录的运行库与资源。

## 完整安装包构建

构建工具采用 [Inno Setup](https://jrsoftware.org/isdl.php) 6.7.3，安装器模板位于 `scripts/installer/kongxiaozhu.iss`。工具仅用于开发打包，不要求同学安装。首次准备：

```powershell
& .\scripts\bootstrap-installer-toolchain.ps1
```

脚本下载官方 GitHub Release，校验固定 SHA-256 和 `Pyrsys B.V.` 有效 Authenticode 签名后，将编译器安装到项目 `.cache/installer-toolchain/inno-setup-6.7.3`，不创建开发工具快捷方式或文件关联。安装工具本身会注册当前用户的卸载项。简体中文语言文件取自官方源码固定提交，另行校验 SHA-256。验证记录保存在同一缓存目录的 `toolchain-verification.json`。网络或签名校验失败会停止，不绕过系统检查。

发布顺序：

1. 完成版本号、构建、计算与桌面验证。
2. 用 `scripts/package.mjs` 生成 `release/控小助-版本-win32-x64`。
3. 运行该发行包的桌面验证，确保 `evidence/packaged-smoke.json` 指向此发行目录且 `passed=true`。
4. 执行 `scripts/finalize-release.mjs`，加入验证记录并更新正式发布清单。
5. 构建完整安装包：

```powershell
& .\scripts\build-installer.ps1
```

输出为 `release/控小助-版本-安装包.exe` 及 `.build.json`，后者记录安装包、发布清单、编译器的哈希。构建逐文件核对正式清单，只打入已验证的文件；拒绝目录链接、越界路径、重复条目、缺失计算线程和不匹配的应用元数据。已有同名安装包不会被静默覆盖。可用 `-CompilerPath` 指定编译器，用 `-Version 0.1.2` 对历史已验证发行包制作测试安装器。

## 安装、升级与数据保留

- 同学收到完整 `控小助-2.2.0-安装包.exe` 后双击，按中文向导安装。默认位置为当前 Windows 用户桌面的 `控小助程序`。
- 安装不需要管理员权限。更新前先在控小助内保存并正常退出；如果目标程序还在运行，安装器拒绝覆盖，不强制结束进程。
- 安装器只能覆盖具有控小助发布清单的非空文件夹。无关文件夹、目录联接、系统目录、桌面根目录及实验数据目录会被拒绝。
- 稳定 AppId 保持不同版本共用同一卸载项。将新版安装到同一位置即可升级。安装器只替换自身所含的程序文件；不会清空任意目录，也不会操作 `%APPDATA%\控小助`。
- 卸载只删除安装器记录的程序文件；用户实验与模型设置保留，重新安装后仍可读取。便携版本留下且不属于安装器清单的文件不主动删除。
- 本项目尚未配置发行者代码签名证书。安装包的构建证据及 SHA-256 可校验完整性，但不等同于 Windows 已认可的发行者签名。不要要求用户关闭 Defender 或绕过安全检测。

## 安装器验收

使用同一个完整 EXE 进行隔离验收：

```powershell
node .\scripts\installer-lifecycle-check.mjs --version 2.2.0 --from-version 2.1.0
node .\scripts\installer-lifecycle-check.mjs --version 2.2.0 --fresh
```

需先有两个版本的完整安装包。未指定 `--from-version` 时验证同版覆盖安装；不能将其称为跨版本升级测试。

`--fresh` 先全新安装目标版本，再检查同版覆盖；报告另存 `evidence/installer-lifecycle-版本-fresh.json`，不会覆盖跨版本报告。1.0.1 的两组测试使用同一个 EXE，分别为 10／10 通过；新装组也通过真实主页进入实验和模型设置。历史 1.0.0 报告与安装包继续保留。

测试目录为项目 `.test-data/installer-版本-时间戳`。`/KXISOLATED=1` 只关闭真实桌面/开始菜单快捷方式与系统卸载注册，程序解包、路径保护、升级与卸载仍执行同一安装器代码。测试应用通过 `KX_TEST_DATA_DIR` 使用独立数据目录，避免触碰真实实验和密钥。

验收覆盖：无关非空目录拒绝覆盖、安装后全量文件哈希、计算线程实际运行、正在运行时拒绝升级、正常退出、覆盖升级保留实验与模型设置、旧实验重新计算、卸载保留数据。证据为 `evidence/installer-lifecycle-版本.json` 和测试目录下的安装日志。只有 `passed=true` 才能宣布安装流程通过；`.build.json` 成功仅表示构建成功。真实桌面快捷方式与系统卸载注册需在最终桌面安装后另行核验。
