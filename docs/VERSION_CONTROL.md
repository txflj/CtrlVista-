## 后续每版交付

1. 开始修改前查看 `git status --short` 和 `git log -5 --oneline --decorate`，确认分支及已有改动，不覆盖别人的工作。
2. 完成源码、适当测试、说明及验证记录；检查暂存差异，排除真实用户数据、密钥、测试临时目录、依赖和编译产物。
3. 将完整修改提交到本机 Git，使用真实版本号创建唯一的 `v版本号` 标签。已交付标签不移动。
4. 保留完整发行包和发布清单；使用 `scripts/install-desktop.ps1` 更新桌面固定程序及快捷方式，具体见 [桌面安装说明](DESKTOP_INSTALL.md)。
5. Git 提交管理源码与文档；`release` 下的程序和 ZIP 由发布文件清单与 SHA-256 管理，不重复放入 Git。

## 用户要求回退时

- 先确认目标标签并保护尚未提交的工作，可保存到独立分支或完成明确的临时提交。不得用 `reset --hard` 或 `clean` 丢弃现有工作。
- 保留当前版本的提交与标签，在独立回退分支或隔离检出中恢复目标版本；回退也应形成可追溯记录。
- 核验目标源码、对应发行包和版本号，执行适当验证后，按相同桌面安装流程替换完整程序目录。旧版本尚无安装脚本时，沿用当前安装工具的路径校验、正常关闭、完整目录替换、快捷方式和启动核对流程。
- `%APPDATA%\控小助` 是实验与设置目录。代码和程序回退不回退、不删除此目录；若未来数据格式变化，应先备份并核对兼容性。
- 不强杀尚未保存的程序；等待正常关闭的保存流程结束。桌面快捷方式仍指向 `<USER_HOME>\Desktop\控小助程序\控小助.exe`。

只读核对命令：

```powershell
git status --short
git log -5 --oneline --decorate
git tag --list
git show v0.1.1:package.json
```
